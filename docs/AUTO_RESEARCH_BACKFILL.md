# 自動化官方歷史行情研究回補 / Automatic Research History Backfill

## 目前資料與目的
2026-11-14 已知正式每日行情：2026-11-11、12、13（三個交易日）；已成功驗證並單獨保存歷史試驗行情：2026-11-04、05、06、09、10（五個交易日）。跨來源稽核已確認近期上市／上櫃同日OHLC吻合，但 TPEx 歷史整股成交量與最新日 OpenAPI 的完整交易時段成交量不一致。

這個自動工作流程只回補**研究用歷史行情**，避免逐天手動操作 GitHub。資料始終存放在 data/market_backfill_pilot，與 data/market_daily 分開；不會自動併入正式選股模型，不代表可立即拿去回測或發布 Top10。

## 使用與排程
- Actions／行動 → Automatic Research History Backfill → Run workflow／執行工作流程（main）。
- 推進程式首次合併 main 時先自動執行一次；之後每日台灣時間 03:35、09:35、15:35、21:35 排程執行，實際執行時間可能延遲。
- 每次最多 20 個新歸檔日期、30 個待查平日、失敗最多 8 次，兩個官方來源每次請求最少相隔 2.5 秒。
- 從最早正式日檔案往前最多 220 個日曆天，優先補最近的尚未存在資料；跳過週末與已保存的日期。
- 每次輸出 research-history-backfill-status artifact（30天），追蹤成功、新資料筆數、被拒日期、原因及已保存研究日期總數。
- 每次只提交 data/market_backfill_pilot 下的公開行情檔案；不會修改任何 Token、私人通知帳本、持股 JSON 或原本22檔監控程式。
- 已存在的歷史行情不會被覆寫；程式不能從「來源無資料」推測是假日，會記下 unverifiedDays，並對異常來源保留可追查原因。
- 若無任何新資料且存在來源錯誤，GitHub 工作標示失敗；若有部分成功和部分拒絕，狀態會顯示 partial_with_unverified_days 而非完整成功。


## 官方休市表驗證

額外使用證交所官方 [holidaySchedule/holidaySchedule](https://openapi.twse.com.tw/v1/holidaySchedule/holidaySchedule) 清單辨識**已公告的平日例行休市日期**，例如2026-10-09、2026-10-26；表內的「開始交易日」與「最後交易日」不是休市，不得誤跳過。這個來源可能只涵蓋目前年度，因此不會用它推測其他年份；若回傳格式異常或來源不可用，就保留所有待查日期，不會憑空編造休市日。未在官方例行休市表、但行情端點無資料的日期（例如首次回補的2026-10-23）繼續標示 unverified，可能是臨時停市或來源異常，**沒有經驗證前不得歸檔**。


官方 OpenAPI 的即時休市清單可能提前切換到2027年度。若當前 API 已不提供2026日期，系統才會使用已核對官方2026年資料的版本化備援檔 config/official_twse_holidays_2026.json；會先驗證年份、來源網址、日期是否為平日且沒有重複，狀態標示 saved_official_reference_year_verified。這不是自行推測或公開市場即時交易日保證：例如2026-10-23仍不在例行休市檔，會保留來源錯誤而非補造行情。

此表是例行休市輔助，不等同完整跨市場歷史實際交易日曆，也不保證兩市場無臨時差異。

## 來源與可信度
- TWSE 官方帶日期 MI_INDEX，歷史成交量單位是股，應與官方最新日可驗證。
- TPEx 官方帶日期 afterTrading/otc，成交量是整股交易口徑，與最新日 OpenAPI 不能直接串接。
- 只保留目前的官方上市／上櫃公司清單內股票；舊日的 IPO／下市母體無法由今日公司名單重建，因此 **pointInTimeUniverse = false**。
- 所有資料都只代表未還原官方開高低收價量，不含除權息、減資還原，也沒有逐日當時可得財報及籌碼。
- 未來即使研究日期累積超過 121 天，仍須確認官方交易日曆、歷史調整和樣本外回測，才能討論實際策略績效。
- README 與量化狀態會持續顯示資料完整情形；本流程不會發布任何偽造的 Top10 或實際勝率。

## 待開發的真正交易系統要求
1. 按時間點建立歷史公司母體及除權息／減資／停牌事件。
2. 只在可比較的同來源價格、量口徑上計算動能／RSI／MACD等技術資料；要使用經調整的價格。
3. 取得三大法人、TDCC、融資、借券、財報發布日期與估值等點時點資料。
4. 對完整因子執行交易日錯位防偷看，5／20日樣本外紙上交易，報酬計入已知約0.04275%手續費、證交稅、滑價與未成交情況。
5. 在完整實證前保留 top10=null、publishable=false，不透過 Telegram 發送選股推薦，不進行自動交易。

追蹤：[Issue #6](https://github.com/leon5281ss/taylorstock-dashboard/issues/6)。


## 多工作流程同時寫入的保護

研究行情回補、正式行情歸檔、官方除權息參考事件各自有資料儲存路徑，但都需要寫回同一個 GitHub main 分支。2026-11-14 第三批歷史回補驗證通過20天資料後，剛好另一份官方資料提交先更新 main，舊程式直接 push 被非快轉衝突拒絕，因此**該20天當次未成功入庫**，不能宣稱已保存65天。

現在共用 scripts/safe_commit_public_data.sh：只允許三個指定公開資料目錄的 .json.gz 變更，拒絕刪除舊檔，先建立本機提交、抓最新 main、進行 git rebase（來源內容衝突則停止），最多嘗試5次普通推送，**不會強制推送或直接覆蓋競爭寫入**。失敗會在 GitHub Actions 紅燈和日誌中保留，後續 GitHub 排程會重新取得官方資料。

當使用者手動更新程式或其他工作流程同時在主分支提交資料時，這個保護能降低不必要的非快轉寫入失敗；不能保證所有網路錯誤或同一檔案不同版本都會自動解決。
